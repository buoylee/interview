# 設計評審 + 工程評審(模擬 Figma comment 串)

> 真實公司裡:PM 把 Figma 連結丟進頻道,設計師和工程師**異步**在畫面上釘 comment,48 小時內清完;
> 吵不完的拉 30 分鐘同步會。每條 comment 的生命週期:提出 → 討論 → **Resolve(必須有結論)**,
> 結論回寫 PRD。沒回寫 PRD 的結論等於沒發生——這是 PM 的紀律。
> 評審者手上拿的 checklist 就是 PRD 第 6 節的三張表 + Nielsen 原則。

## 評審 comment 串(按畫面)

### 🧵 C1 · S1 值班表 · 小美(設計)
> 七態表 S1 空態標「?」——我畫了「8 月尚未排班」變體,但**全新團隊第一次打開、什麼都沒有**呢?
> **大熊**:onboarding 場景,管理員還沒排班,成員進來一片白。
> **阿明(PM)**:接受。空態文案分兩種:成員看「尚未排班,找老張」;管理員看「發布第一份排班 →」引導進 S5。
> ✅ Resolved → PRD 七態表 S1 補全

### 🧵 C2 · S1 · 大熊(後端)
> 極端資料:有人 8 月發起「換 7/18 的班」——**過去的班次**能換嗎?班次今晚 20:00 開始、19:59 發起呢?
> **阿明**:規則補上:只能對「未開始」班次發起;申請過期時間 = min(48h, 班次開始前 2h)。已開始/已過去的班次操作入口直接不出現。
> ✅ Resolved → PRD 加「時間邊界」節,US-2 驗收標準補 2 條

### 🧵 C3 · S2 發起換班 · 小美
> 「回饋班次選填」=Q3 拍板了?單向頂班會不會讓老好人一直吃虧?
> **阿明**:拍板:允許單向(小陳訪談:降低開口成本優先)。公平性問題交給 audit log 可見性(誰老在頂班,月報一目了然),不用規則硬管。
> ✅ Resolved → PRD Q3 關閉,理由記錄

### 🧵 C4 · S3 我的申請 · 小美
> 被拒之後,能不能**立刻對同一班次再發起**?會不會變成騷擾(拒了又來)?
> **阿明**:允許再發起但換對象;對同一人同一班次 24h 內不能重發。防騷擾寫進規則而不是靠自覺。
> ✅ Resolved → 五問表「發起換班」前置條件補全

### 🧵 C5 · S4 收到的申請 · 大熊(⚠️ 本輪最重要的一條)
> 公開徵人兩人同時點「我來接」,kickoff Q1。技術方案:DB 樂觀鎖,先提交者贏。但**第二個人看到什麼**是產品問題,你定。
> **阿明**:第二人看到無責備失敗態(「大熊 3 秒前接走了」),不是報錯彈窗。已畫進 S4 變體。
> **大熊**:另外「接受」那格五問表寫「能否撤銷:?」——接受後表已對調、通知已發,回滾要撤通知+防對方已安排行程,成本爆炸。
> **阿明**:拍板:**接受不可撤銷**。UI 側用「你給出/你得到」攤牌 + 按鈕寫明後果來補償。真要反悔 = 發起一次新換班,或找老張兜底改表。
> ✅ Resolved → 五問表補全,PRD 加「不可撤銷操作清單」

### 🧵 C6 · S5 管理員 · 小美
> CRUD 矩陣「成員」行有「?」:帳號誰建?
> **阿明**:白名單:老張在 S5 維護成員名單(加人/停用),對接公司帳號登入,本工具不做註冊。
> ✅ Resolved → CRUD 矩陣補全

### 🧵 C7 · 通知鏈路 · 大熊
> webhook 掛了(群組服務抽風)怎麼辦?通知丟了,換班卻生效了,比沒通知更危險。
> **阿明**:分級:通知是**盡力而為**,事實源永遠是網頁值班表;webhook 失敗重試 3 次,仍失敗則在 S1 頂部掛橫幅「通知服務異常,請主動查看」。PRD 明確寫「通知非事實源」。
> ✅ Resolved → PRD 第 7 節補強

## 評審產出彙總(回寫 PRD 的 delta 清單)

| # | 來源 | PRD 變更 |
|---|---|---|
| 1 | C1 | 七態表 S1/S5 空態補全(分角色文案) |
| 2 | C2 | 新增「時間邊界」規則;US-2 驗收 +2 |
| 3 | C3 | Q3 關閉:允許單向頂班 |
| 4 | C4 | 重發防騷擾規則(同人同班次 24h) |
| 5 | C5 | Q1 關閉:先到先得+無責備失敗態;接受列入不可撤銷清單 |
| 6 | C6 | 成員 = 管理員維護白名單 |
| 7 | C7 | 通知 = 盡力而為,非事實源;失敗降級橫幅 |

💡 **觀察**:7 條 comment 裡 5 條是三張表的「?」格子直接引來的——表格的作用不是自己填完美,
是**把洞明晃晃留在那裡,讓評審有的放矢**。這就是「完整性」在真實流程裡如何被機械化保證。
