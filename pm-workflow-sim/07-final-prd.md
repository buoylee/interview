## 1-5 節

背景/目標/非目標/角色/Stories 同 [v1](03-prd-draft.md),外加:

**US-2 驗收補充(時間邊界)**
- Given 班次已開始或已過去, Then 該班次不出現任何換班入口
- Given 申請存續中, When 到達 min(48h, 班次開始前 2h), Then 自動過期並通知發起人

**不可撤銷操作清單**(UI 必須在操作前攤牌後果):接受換班、拒絕換班。反悔路徑 = 發新申請或找管理員兜底。

## 6. 規則彙總(工程直接照抄)

| 規則 | 內容 |
|---|---|
| 發起前置 | 班次屬於自己、未開始、無進行中申請 |
| 過期 | min(48 小時, 班次開始前 2 小時) |
| 重發限制 | 同對象同班次 24h 內不可重發 |
| 公開徵人 | 先到先得(樂觀鎖),後到者見無責備失敗態 |
| 通知 | webhook 重試 3 次;失敗掛 S1 橫幅;通知非事實源 |
| 權限 | 成員白名單制,管理員維護;S5 僅管理員可見 |

## 7. 拆票(給 Jira/Linear,按依賴排序)

| # | Story | 驗收要點 | 估點 |
|---|---|---|---|
| T1 | 值班表讀取 + 今日值班(S1 含四態:空/載/正常/錯) | 分角色空態文案 | 3 |
| T2 | 成員白名單 + 登入對接 | 停用成員即失去操作權 | 2 |
| T3 | 發起換班(S2)+ 我的申請(S3 全狀態機) | 前置條件校驗、時間邊界 | 5 |
| T4 | 響應換班(S4)+ 併發控制 | 樂觀鎖、無責備失敗態、表對調原子性 | 5 |
| T5 | 過期任務(定時器) | min 規則、過期通知 | 2 |
| T6 | webhook 通知 + 降級橫幅 | 重試 3 次、橫幅出現/消失 | 3 |
| T7 | 管理員改表 + audit log(S5) | 每筆含操作人/來源/原因 | 3 |

*估點是相對複雜度(fibonacci),sprint planning 時工程團隊自己估,PM 不代估——這裡填的是大熊的數。*
